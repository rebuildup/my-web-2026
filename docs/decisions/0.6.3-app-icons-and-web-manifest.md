# Decision — 0.6.3 ファビコン / Apple Touch Icon / Web App Manifest

> Status: **Accepted**
> Issue: #504
> Target version: 0.6.3
> Grounded: 2026-10-18

Issue #504「favicon・Apple Touch Icon・manifestを整備」の実装判断を固定する。
既存ファビコン（Issue #285）は維持し、iOS ホーム画面アイコンと Web App Manifest を
**必要な範囲**で公開する。PWA のオフライン動作は宣言しない。

## 1. 何を公開するか / 何をしないか

| 公開するもの | 判断 |
| --- | --- |
| `rel="icon"` SVG（`/favicon.svg`） | Issue #285 の既存アセットをそのまま維持する |
| `rel="icon"` PNG 16 / 32 | SVG を読めない埋め込み・古い Safari のフォールバック |
| `rel="apple-touch-icon"` 120 / 152 / 167 / 180 | iOS がホーム画面で実際に求めるサイズ |
| `public/site.webmanifest`（`/site.webmanifest`） | name / short_name / lang / dir / id / start_url / scope / display / background_color / theme_color / icons のみ |
| manifest icons 192 / 512（`purpose: any`）+ 512（`purpose: maskable`） | Android / Chrome のランチャー向け |
| `theme-color` meta 2 本（light / dark） | サイトの 2 appearance（Issue #290）に合わせる |
| `_headers` の `/site.webmanifest` と `/icons/*` ルール | メディアタイプとキャッシュ方針の明示 |

| 公開しないもの | 理由 |
| --- | --- |
| service worker / オフラインキャッシュ | Issue #504 が明示的に禁止。プラットフォームにオフライン契約が無い |
| `apple-touch-startup-image` | 起動画面のアセットが存在しない。臆造しない |
| `share_target` / `shortcuts` / `display_override` / `categories` | 別 Issue の obligation 決定。gate で拒否する（§4） |
| `screenshots`（rich install UI 用） | 対応する device 実測が無く、条件を満たせない |
| 個人データ（氏名・連絡先・SNS handle） | manifest は公開済みサイト情報の写像に留める（§3） |
| 新しいブランド表現 | マークは既存 `public/favicon.svg` の円のみ（§2） |

## 2. マークの由来（推測の混入を止める）

`public/favicon.svg` の円（`#0000FF`）がマークの唯一の source of truth。
`scripts/generate-app-icons.mjs` がそこから PNG を生成し、**不透明キャンバスを敷くだけ**で
新しい形状・新しい色は作らない。

- 不透明キャンバスが必要な理由: iOS は alpha を持つ `apple-touch-icon` を**黒地に合成**する。
  生成スクリプトは `.flatten()` で alpha channel 自体を落とす（`hasAlpha === false`）。
- キャンバス色 `#ffffff` とマーク色 `#0000FF` の**帰属は異なる**。gate の実挙動をそのまま書く:
  - **キャンバス色だけ**が `src/editorial/tokens.ts` に実在することを gate が要求する
    （§4 の検査 3 の隅ピクセル照合と検査 6 の palette 照合）。生成スクリプトが使う
    `bg.canvas` の light step（`colors.neutral.0`）と token 側が同じ値であることを gate が縛る。
  - **マーク色は token palette 照合に入っていない**。`#0000FF` は `src/editorial/tokens.ts` に
    存在せず（`grep -i 0000ff src/editorial/tokens.ts` は 0 件）、gate が照合する palette は
    キャンバス色・manifest の `theme_color` / `background_color`・`theme-color` meta 2 本だけである。
    `public/favicon.svg` 自身が「未混色のブラウザ標準青（`原色の青`）で、デザインされたブランドマークでは
    なく未設定の状態として読ませる」ためのプレースホルダーであると明記しているため、
    本 ticket はその色を design token に昇格させず、**favicon がマーク色の唯一の owner** とする。
    これを token に昇格させるかどうかは owner 決定事項であり、本 ticket では決めない（§6）。
- gate が実際に守れるのは「PNG の中心ピクセル = `public/favicon.svg` の `fill`」という一致だけである
  （§4 の検査 3）。つまり favicon 側の色だけを変更して `pnpm run generate:app-icons` で再生成すれば
  gate は緑に戻る。**gate はマーク色の palette 所属を要求せず、favicon 側の色変更自体も禁じない**
  という点は上の帰属と不可分であり、誤読しないこと（token 化は owner 決定: §6）。
- `maskable` 用の円だけは 60% に縮尺する。Web App Manifest 側が定める safe zone は
  「中央 80% の円」であり、端まで 접した円は launcher のマスクで切れてしまうため。
  背景は full-bleed なので crop の縁は見えない。

## 3. 公開情報の authority

`docs/personal/knowledge-model.md` の「Visibility is independent from truth」/「Source authority is contextual」に従い、
manifest は**既存の公開 surface の写像**であり、独立した personal data を持たない。

- `name` / `short_name` = `my-web-2026`（`__root.tsx` の `<title>` と同一文字列。ここだけが唯一の source）。
- `lang: "ja"` = `<html lang="ja">` と一致。
- `start_url` / `scope` / `id` は origin  相対 path のみ。外部 origin を参照しない。
- 個人データ・連絡先・SNS handle は manifest に入れない。`/contact` が公開する内容は
  contact surface の authority（freshness gate）に属し、icon の義務ではない。

## 4. 監査対象（gate）

`scripts/check-app-icons.mjs`（`validate:fast` に組込み、`pnpm run check:app-icons`）が fail-closed で検査する:

1. `public/site.webmanifest` が parse でき、必須 member を持ち、**ticket が決定した member のみ**を持つ
2. `APP_ICON_LINKS` の全 `<link>` が実在ファイルへ解決し、`sizes` が実ピクセルと一致する
3. 全 PNG が alpha channel を持たず、中央ピクセル = `public/favicon.svg` の `fill` /
   隅ピクセル = palette 由来の `#ffffff`。**マーク色の palette 所属は問わない**（§2 / §6）
4. `public/icons/` の全ファイルが head link か manifest から**ちょうど 1 回**参照される（orphan / 重複なし）
5. Issue #285 の SVG favicon と iOS の 4 サイズが宣言されたまま残っている
6. manifest の `theme_color` / `background_color` と `theme-color` meta 2 本の値が
   `src/editorial/tokens.ts` に実在する（設計システム外の色を持ち込めない）
7. `_headers` が manifest の `Content-Type` を固定し、`/icons/*` を revalidating に保つ
8. `src/**`（`.ts` / `.tsx` / `.js` / `.jsx` / `.mjs` / `.cjs`）に service worker 登録が無い。
   走査対象は生のソース文字列で**コメントも含む**: 「`navigator.serviceWorker` という語を含む説明
   コメント」だけを追加しても赤になる。fail-closed として意図的であり、該当する場合は文言を書き換える
   （tripwire が prose を除外する設計は、実装が prose に依存し始めた瞬間に漏れるため）。

unit test（`scripts/check-app-icons.test.mjs`）は上記各項目の **mutation test** で、
gate が drift を検出できない場合（false green）を自ら検出する。

## 5. 検証の 3 層

| 層 | 対象 | 何が証明されるか |
| --- | --- | --- |
| static gate（Node） | head link / manifest / ファイル | 宣言された契約が整合していること。CI ログには「マーク色は palette 外・キャンバス色は palette 内」の帰属も出る |
| integration（workerd / `SELF.fetch`） | 実 SSR HTML | head merge が route 固有 `head()` を持つページでも icon family を残すこと、および SSR 出力にオフライン宣言が無いこと |
| E2E（Chromium） | 実ブラウザ | 各 PNG が宣言サイズで decode され、**配信された** manifest の member 集合がこの ticket の契約と一致すること、manifest が JSON として fetch されること |

検証画面: `docs/verification/web/app-icons-preview.png`（local preview の実 Chromium による取得）。
生成スクリプトは `scripts/capture-app-icons-preview.mjs`（`pnpm run capture:app-icons-preview [baseURL] [outPng]`）。
route `/contact`、Chromium、viewport 1180 × 1460 CSS px、`deviceScaleFactor: 2`、`colorScheme: light`、
`waitUntil: networkidle`、clip は検証パネルの bounding box、を実行条件としてスクリプト内に固定している
（raw viewport の撮影だと末尾が切れるため）。実行前提として配信サーバー（`pnpm run preview`）が必要。
秘密情報は含まれない（読み取るのは `document.head` と静的アセットのみ）。

**取得済み画像の再生成検証**: 本 branch でコミットしたスクリプトから再取得した PNG は、
コミット済みの `docs/verification/web/app-icons-preview.png` とバイト一致した（同一 build・同一条件）。

## 6. 既知の制約 / 残リスク

- **マーク色 `#0000FF` は design token ではない（owner 未決）**: §2 のとおり、この色は
  `src/editorial/tokens.ts` の palette 外にあり、gate も palette 所属を要求しない。`public/favicon.svg`
  のコメントが述べる「未設計のプレースホルダー状態」という位置づけのまま、iOS ホーム画面 /
  Android launcher / install prompt というアプリ同等の brand surface に出荷している。Issue #504 の
  指示（既存 favicon の複製）に従った帰結であり、本 ticket では解決しない。次の 2 つは
  **owner 決定**であり、ticket を立てて決めること:
  1. `#0000FF` を token に昇格させ、gate もマーク色の palette 所属を要求する（§2 / §4 の記述も変更）。
  2. palette 外を許容する旨を、明示的な escape hatch として gate に定義する（現状の実効を明文化）。
  どちらを採っても、§2 / §4 の記述は実装に合わせて書き換えること。
- **`background_color: "#ffffff"` と dark appearance の install splash**: manifest は
  `background_color` を 1 色しか持てないため、Android の install splash / launch background は
  dark 設定のユーザーでも白になる。下の `theme_color` の項と違い、head 側の 2 本では表せない。
  gate は palette 所属しか問わない。実機での見え方は未確認であり、変更する場合は owner 決定
  （インストール時の既定画面というユーザー体験の表面積を持つ）。
- **`Content-Type` の production 実機確認**: `_headers` の `Content-Type: application/manifest+json` は
  local preview（`vite preview` が同ファイルを parse）で確認済み。`_headers` 規則の有無の 2 経路とも
  同値になることは独立に確認済み。Cloudflare Workers Static Assets 実機での応答ヘッダは
  production Smoke で確認する項目として残す。`.webmanifest` 拡張子自体も同値のマップを持つ。
- **`purpose: "maskable"` の実 launcher 確認**: 60% 円 + full-bleed 背景は safe zone 仕様から導出した
   ものの、Android 実機 / 実 launcher の見た目は未確認。視覚判断は owner の目を通す必要がある。
- **`display: "standalone"`**: manifest 仕様上 1 色しか指定できない `theme_color` のため、manifest 側は
  appearance 変化しない `brand.700`、head 側は light / dark の 2 本で表す。サイト側に offline が無い
  ことを利用者が誤解しないよう、PR / docs では offline 非宣言を明示する。
- **`theme-color` meta の生 hex の重複**: `<meta name="theme-color" content="…">` は CSS 変数を
  参照できないため、`src/editorial/tokens.ts` と同じ生 hex が `src/routes/__root.tsx` にも存在する
  （2 箇所の重複）。gate が「両方が palette に実在する」ことを要求するため、値がずれた場合は検出される。
- **`share_target` 等を後々足す場合**: `ALLOWED_MANIFEST_MEMBERS` を拡張せずに追加すると gate が落ちる。
  これは意図的（member 追加 = obligation 決定）であり、Decision を先に書くこと。
