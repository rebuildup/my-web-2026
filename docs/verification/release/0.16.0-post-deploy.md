## 5. Catch-up / LKG / partial failure

- **Catch-up**: launchd `StartCalendarInterval` の夕方枠（21:00 / 21:30
  JST）が同日 catch-up を担う設計（`docs/runbook/github-activity-sync.md`
  §Scheduling）。`.tmp/sync-github-activity.lock` による overlap 防止は
  script 冒頭で確認済み。今夜の定期枠の実測は翌日確認事項とする。
- **LKG**: ingest 失敗時に前回 snapshot が配信継続することは v0.15.x の
  実障害で実証済み（v0.15.2 post-deploy §3: 413 失敗中も LKG で 200 配信）。
  snapshot 不在時の 200 未観測 SVG（#1286）により cold start でも
  honest-empty にならない。
- **Partial failure**: `snapshot-health` は source 単位で
  `fresh`/`stale`/`absent`/`failed` を報告し、stats runbook の障害表が
  単一 source 失敗時の縮退（rank null 化・他指標継続）を規定。
  本リリース時点では全 source fresh であり、故障注入は行わない
  （設計 + 既存障害実績をもって受理）。
