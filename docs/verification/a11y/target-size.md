# タップ・クリックターゲットとドラッグ代替を検証する（Issue #401）

> 検証対象: 反応ピッカー / nav / filter の 3 面。
> 判定の物差しは [WCAG 2.2](https://www.w3.org/TR/WCAG22/) の
> **SC 2.5.8 Target Size (Minimum)、レベル AA**。

この Issue は**判定できる範囲**だけを機械に掛ける。判定は 2 段構えで、
同じ Issue が 2 つの入口を持つ。

| 段 | 入口 | 決まるもの | 決まらないもの |
| --- | --- | --- | --- |
| 静的 | `pnpm run a11y:target-size:check` | 要素が**宣言している**ヒット領域のサイズ、宣言された例外の妥当性、ドラッグ専用操作の有無 | 描画された箱が実際にどれほどの大きさか（描画結果はソースに書かれない） |
| 実測 | `pnpm run capture:a11y-target-size` | Chromium が測った**箱**、例外の実測（inline / spacing） | 作者の意図、代替の適切さ、押しやすさ |

片方だけでは結論にならない。静的段は「作者が 16 px と宣言した」という
**宣言**を裁き、実測段は「描画された箱が何 px か」という**結果**を測る。
宣言が小さければ描画が後から大きくなっても欠陥であり、描画が小さければ
宣言が何を言っていようが欠陥である。

## 適用対象（3 面）と対象外

適用対象は Issue #401 が名指しした 3 面だけで、その面が持つファイルが
対象である。

| 面 | ファイル | 静的ゲートが見る対象 |
| --- | --- | --- |
| 反応ピッカー | `src/home/reactions/widget.tsx` | 反応チップのボタン（`height: '8'` = 32 px）、picker を開くボタン（`height: '9'` = 36 px） |
| nav | `src/editorial/nav/PublicNav.tsx` | ロゴの `<a>`、nav の `<a>`（`NavLink`）、モバイルメニューのボタン（`height: '9'` = 36 px） |
| filter | `src/portfolio/components/FacetFilter.tsx` | ファセットのチップ（`h: '8'` = 32 px）と解除ボタン |

**対象外は黙って無視していない。** ゲートは `src/**` のうち対象 3 ファイル
以外をすべて除外し、その件数を理由つきで出力する（今回の除外は 140
ファイル）。理由はこの Issue が 3 面だけを名指ししており、別の面の欠陥を
この Issue の名前で裁くことにならないためである。ほかの面の標的サイズは
**それぞれの面の Issue の担当**であり、このゲートはそこを代行しない。

## 基準: 24 × 24 CSS px と 4 つの例外

SC 2.5.8 は 24 × 24 CSS px を要求し、次の 4 つを例外として認める。例外は
**黙って無視しない**。どの例外がどう決まるかを表で示す。

| 例外 | 決める段 | 条件 | このリポジトリでの扱い |
| --- | --- | --- | --- |
| inline | 実測 | 対象が文の中にあり、大きさが周囲の行の高さで決まる | **宣言したサイズ**が 24 px を下回っていても inline 扱いにはならない。実測段が `display` を読む |
| spacing | 宣言 + 実測 | 対象の中心に 24 px の円を置いたとき、ほかの対象の円や外接矩形に交差しない | 作者が理由つきの宣言をし、実測段がその主張を**検算**する。幾何が支持しない主張は合格ではなく失敗 |
| user-agent control | 宣言 | 大きさがユーザーエージェントが決めており、作者が変えていない | 理由つきの宣言が必要。宣言の宣言は 0 件（下の表） |
| essential | 宣言 | 特定の表示が本質的に必要 | 理由つきの宣言が必要。宣言の宣言は 0 件（下の表） |

宣言のみの例外（user-agent control / essential）は
`scripts/check-a11y-target-size.mjs` の `SHIPPED_EXCEPTIONS` に
1 行ずつ（面・セレクタ・種類・理由）書く。**今回は 0 件**で、出荷の 3 面は
宣言のみの例外を必要としない。0 件でも件数を出力するので「見たが何も
なかった」ことが読める。理由のない宣言は例外ではなく、**ラベルの付いた穴**である。

## 静的ゲートが読むもの

`scripts/check-a11y-target-size.mjs`（純 Node / オフライン /
status-only）は次の規則を適用する。

| 規則 | 意味 |
| --- | --- |
| `shipped-target-undersized` | 出荷の対象が 24 px を下回るヒット領域を**宣言**している |
| `shipped-drag-without-alternative` | 出荷の対象がドラッグ操作を持ち、クリック（またはキーボード）代替がない |
| `target-specimen-undersized` | fixture が 24 px を下回るサイズを宣言し、有効な例外を宣言していない |
| `target-specimen-exception-invalid` | fixture が SC 2.5.8 の 4 例外以外の種類を宣言した、または理由 없이宣言した |
| `target-specimen-drag-only` | fixture がドラッグ専用操作を再現している |
| `fixture-*`（6 規則） | fixture が「正常」「違反」の状態を再現していない（空の fixture、壊れた fixture、名前が変わった fixture） |

読み取る宣言は Panda の `css({ … })` とインラインの `style={{ … }}` の
両方で、`h` / `w` / `size` / `minH` / `minW` と `height` / `width` /
`min-height` / `min-width` を同じ物として扱う。値は Panda の `sizes` と
`spacing` のスケール（0.25 rem 刻み、根本 16 px）を解決する。`min-width: 0`
は「下限がない」宣言であって「小さい対象」の宣言ではないため、無視する。
レスポンシブな宣言（`{ base: '4', md: '6' }`）は**最小の段**で判定する。

今回の実測（静的段）:

| 面 | 対象数 | 24 px 以上を宣言 | 24 px 未満を宣言 | ソースから判定不能 |
| --- | --- | --- | --- | --- |
| public nav | 3 | 1 | 0 | 2 |
| reaction picker | 2 | 2 | 0 | 0 |
| facet filter | 2 | 2 | 0 | 0 |

「ソースから判定不能」は、大きさが `font-size` と余白から決まる標的なので
ある（nav のリンクの箱は 29 px）。**小さいことを意味しない**ので、欠陥では
なく実測段の担当として扱う。

## 実測段が読むもの

`scripts/capture-a11y-target-size.mjs` は Chromium で次を測る。

1. **fixture 標本**（`scripts/fixtures/a11y-target-size/{pass,fail}`）。
   ハーネスが fixture ファイル本体を読み込むので、ゲートと実測段が別の
   定義を持つことがない。
2. **出荷の 3 面**。ローカルのプレビューサーバ（`scripts/e2e-local-bootstrap.mjs`、
   Playwright の `webServer` と同じもの）がビルド済み Worker を loopback に
   配信し、対象面を開いて各対象を測る。

測定は `getBoundingClientRect()`（境界ボックス = 実際に押せる箱）。
`display: none` などで**箱を持たない要素は対象ではない**（押せないので
敲ける場所がない）ので除外し、その件数を記録する。

面が動いている最中に測ると「測了一半」の結果になる（picker はダイアログ
を開いたあとに絵文字を並べる）。そのため**対象数が 3 回連続で変わらな
くなるまで**待つ。待ちには上限があり、落ち着かない面は「測り切れな
かった」と報告して中断する（動いている対象を測った値を測定と呼ばない）。

### 出荷の 3 面の実測（2026-10-23）

| 面 | 経路 | viewport | 測った対象数 | 箱を持たない対象 | 最小の箱 | 判定 |
| --- | --- | --- | --- | --- | --- | --- |
| public nav（desktop） | `/about` | 1280 × 900 | 7 | 7 | 27 × 27 px | 適合 |
| public nav（モバイルパネル） | `/about` | 600 × 800 | 8 | 6 | 27 × 27 px | 適合 |
| facet filter | `/portfolio` | 1280 × 900 | 4 | 0 | 32 × 32 px | 適合 |
| reaction picker（ダイアログ） | `/design-system` | 1280 × 900 | 109 | 1 | 30 × 30 px | 適合 |

nav の「箱を持たない対象 7 件」は、desktop 幅で隠れているモバイル
パネルのリンクと、desktop 幅では隠れているボタンである。逆も
同様（モバイル幅では desktop のリンク列が隠れる）。**隠れている対象は
対象ではない**という判断は画面ごとに記録する。

picker は `/design-system` の fixture 経由で測る。ホームの picker は
consumer API key（`MY_WEB_2026_CONSUMER_API_KEY`）が設定された
deployment でのみ描画され、key のない環境には `<dialog>` 自体がない。
Issue #394 が出荷している `PickerModal` をそのまま描画する fixture
（`src/routes/design-system/sections/ReactionPicker.tsx`）を用意すると、**key の有無にかかわらず**同じ出荷要素を測れる。測る対象は本物の
要素で、コピーではない（データだけ固定する、Issue #486 の CLS fixture
と同じ考え方）。

### fixture の実測

| fixture | 期待 | 実測 | 判定の根拠 |
| --- | --- | --- | --- |
| `pass/01-minimum-target.tsx` | 適合 | 24 × 24 px | 最小値そのもの |
| `pass/02-oversized-target.tsx` | 適合 | 40 × 40 px | 最小値より十分大きい |
| `pass/03-inline-target.tsx` | 適合 | 131 × 18 px、`display: inline` | inline 例外（実測で決定） |
| `pass/04-spacing-exception.tsx` | 適合 | 16 × 16 px が 2 つ、間隔 24 px | spacing 例外（宣言 + 実測の検算が一致） |
| `fail/01-undersized-target.tsx` | 違反 | 16 × 16 px | 例外なし |
| `fail/02-tight-neighbours.tsx` | 違反 | 16 × 16 px が 2 つ、間隔 2 px | spacing 例外の**主張が幾何で支持されない** |
| `fail/03-drag-only.tsx` | 静的には違反 | 24 × 24 px | 大きさは適合。ドラッグ代替の欠如は静的に決まる |

`fail/02` は実測段の**反証**（negative control）である。宣言された
spacing 例外を「宣言だから通す」のではなく、幾何で検算して**拒否する**。
ここに 2 px の間隔と 24 px の間隔の 2 つも並び、判定が主張の正しさではなく
主張と幾何の一致で決まっていることが読める。

## 機械検査と人の評価

| 主張 | どう調べるか |
| --- | --- |
| 対象の宣言されたヒット領域が 24 px 以上である | **機械**: 静的ゲート |
| 描画された箱が 24 px 以上である | **機械**: 実測段 |
| 例外は宣言され、理由があり、主張が幾何と一致する | **機械**: 静的な宣言検査 + 実測の検算 |
| ドラッグ操作にクリック（またはキーボード）代替がある | **機械**: 静的ゲート（`onClick` / ネイティブの操作可能要素 / `tabIndex` + `onKeyDown`） |
| 24 px の対象を親指で押しやすい | **人**: 実機（実物のスマートフォン）での確認 |
| spacing 例外が「測り合いの結果」ではなく良い設計判断である | **人**: 設計判断 |
| ドラッグ操作が正しい操作方式である（そもそも代替が必要か） | **人**: 設計判断 |

上の「機械」の行が緑でも、適合の主張には
**スクリーンリーダー実機確認と実機でのタップ確認**が加わる。この
記録は**判定の根拠**であって適合の証明ではない。

- 下段: 出荷の 3 面のスクリーンショット。同じ重ね描きをかぶせている。

### Issue が名指ししたファイル名からの乖離 2 点

Issue #401 は `docs/verification/a11y/tap-target-overlay.png` と書いて
いる。乖離は 2 点に分けて理由がある。

| 乖離 | 理由 |
| --- | --- |
| **拡張子**（`.png` → `.webp`） | リポジトリの規約で検証画像は WebP のみ。Chromium は PNG しか書けないので、`.tmp/` に PNG を取り、既存の `sharp`（幅 1600 px 上限・品質 80・300 kB 予算）で WebP に変換して `.tmp/` の PNG を削除する。このスクリプトは `.webp` 以外の出力先を**拒否**する |
| **ファイル名**（`tap-target-overlay` → そのまま） | 乖離なし。Issue の名をそのまま使っている。**主題**は「対象の箱に 24 px の最小値を重ねた図」であり、対象は Issue が名指しした 3 面 + fixture 標本である |

## 誤検知が起きたときの対応

誤検知（本来は適合なのに赤になる、あるいは本来は違反なのに緑になる）が
起きたら、次の順で調べる。**ゲートを緩めて緑にする手順は禁止**である。
判定の範囲を変えるなら**この記録に宣言として書く**。

1. その assertion がその route / その面で成立するか。別の面の値を持ち
   込んでいないか。
2. 日付・データ・設定に依存していないか（picker の絵文字一覧が後から
   増えたら、実測が「動いている最中」だった可能性がある。実測段は対象数
   が 3 回連続で変わらないまで待つ）。
3. 対象外の面の問題が混ざっていないか。対象外にしたものは、理由と
   対象外の件数がゲートの出力に出ている。
4. 例外が「宣言なし」で無視されていないか。宣言は理由つきの行であり、
   理由のない宣言は `target-specimen-exception-invalid` になる。
5. それでも判断が要るときは**owner に判断を仰ぐ**。閾値（24 px）の緩和、
   対象面の拡大、例外の黙示はいずれも owner の決定である。

具体的な例: nav のリンク（29 px）が赤くなった場合は、nav の
`paddingBlock` を変えた影響である。filter のチップ（32 px）が赤くなった
場合は `h: '8'` を変えた影響である。picker の検索入力が赤くなった場合は
picker 側の実装（`emoji-picker-react`）であり、この Issue の対象範囲の
外側として扱うかを owner と決める。

## 取りこぼしと誤検知の確認（attack）

ゲートが「違反を検出する」「適合を誤って指摘しない」ことを、故意に壊して
確かめた。注入したコードは**すべて復元**し、commit には含めていない。

| 注入 | 静的な段 | 実測の段 | 結果 |
| --- | --- | --- | --- |
| A. filter に `h: '4'`（16 px）の対象を 1 個足す | `shipped-target-undersized` を報告、exit 1 | 走らない（gate が赤なら測らない） | 検出 ✓ |
| B. nav に `draggable` と `onDragStart` だけの `<div>` を足す | `shipped-drag-without-alternative` を報告、exit 1 | 走らない | 検出 ✓ |
| C. filter に大きさを宣言しない対象（`fontSize: 'xs'` と `alignSelf: 'flex-start'`）を足す | 「ソースから判定不能」（違反ではない） | 35 × 12 px を実測 → 違反、exit 1、**成果物を書かない** | 実測の段が検出 ✓ |
| D. `pass/01-minimum-target.tsx` を 16 px に縮める | `fixture-pass-violation` を報告、exit 1 | 走らない | 検出 ✓ |

A と B は宣言だけで決まる違反、C は宣言からは見えないが描画では 24 px を
下回る違反である。**2 段構えの理由がここに出る。** 静的な段だけなら C を
見落とし、実測の段だけなら A・B・D を見落とす。

B は実装の穴を暴いた。最初は「対象」＝操作可能な要素という前提でドラッグ
規則を判定していたが、**ドラッグ専用の操作はロールも役割も持たない素の
`<div>` に居る**ため、その前提ではいちばん見つかりにくい要素が検査から
漏れていた。以来、ドラッグ規則は**要素の役割に関係なく、ドラッグの
宣言があるすべての要素**に適用する。

C は実測の段が検出し、**成果物を書かずに exit 1** した（測った図を
残さない。壊れた契約の写真を残すため）。

復元後、gate は緑（exit 0）へ戻り、検証画像は 4 つの適合標本・3 つの
違反標本・出荷の 3 面の状態で再生成された。

## 既知の制約

- **静的ゲートは宣言しか読めない。** 大きさが `font-size` と余白から決まる
  対象は「判定不能」として扱い、実測段の担当になる。宣言で 24 px を下回る
  対象は、描画が後から大きくなっても違反として扱う（宣言は作者の主張で
  あり、小さい主張は描画が補おうとしない）。
- **inline 例外は実測の `display` で決める。** 作者が対象を `display: inline`
  にすれば inline 例外に入れる余地があるため、静的段は「宣言したサイズが
  24 px を下回る」ことを先に違反として扱う。実測段の inline 救済は、
  宣言されたサイズを持たない対象（文の中で大きさが行の高さで決まる対象）
  にだけ効く。
- **実測段は Chromium の一つの viewport で測る。** 画面幅が変わると折り返し
  方は変わる。今回は 1280 × 900 と 600 × 800 の 2 種を測ったが、ほかの
  viewport での折り返し方は測っていない。
- **picker の絵文字一覧の個数は実行ごとに変わる。** 109 個だった記録が
  あるが、これは library 側の描画依存である。判定に使うのは**最小の箱**
  （今回は 30 px）であり、個数は参考値である。
- **このゲートは 3 面以外を走査しない。** 残りの面の標的サイズは未検証で
  あり、「満たしている」ではなく「測っていない」を意味する。

## 再現コマンド

```sh
# 1. 静的ゲート（pnpm run validate:fast にも入る）
pnpm run a11y:target-size:check

# 2. ゲートと実測段の単体テスト
node --test scripts/check-a11y-target-size.test.mjs
node --test scripts/capture-a11y-target-size.test.mjs

# 3. ブラウザ実測（ビルドが必要: pnpm run build）
pnpm run capture:a11y-target-size
```

実測段は `.tmp/a11y-target-size/report.json` に書き出す（実測値・判定・
WCAG 対応・viewport・エンコード条件）。ハーネスは
`.tmp/a11y-target-size/harness` に生成し、Vite でリポジトリの
`postcss.config.mjs` を使ってビルドし、loopback のポートで配信する。

capture は**判定に矛盾したら成果物を書かずに終了する**（終了コード 1）。
静的ゲートが赤ならハーネスも測らず、gate の報告だけを出して中断する。
