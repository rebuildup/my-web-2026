# Markdown 表示の安全境界

`src/portfolio/markdown.lexer.ts` が解釈する block は 6 種類 — 見出し / 段落 / リスト / コード / 引用 / 罫線 — で、inline は 5 種類 — テキスト / 強調 / 斜体 / コード / リンク — である。この範囲外の構文は **削除されない**。解釈できないまま、書き換えもされないまま、本文として残る。

## 見出しは 3 段階まで

`#` / `##` / `###` の 3 段階だけが見出しになる。`####` は見出しではない。4 つの `#` はそのまま段落の中に残る。

### 数値・否定・権限を壊さない

レンダラは本文を書き換えない。数値 `3` は `3` のまま、否定句「これはレビュー済みの結論ではない」は同じ文字列のまま残る。この範囲を決める権限は `src/portfolio` が持ち、Markdown 文法の実装は lexer の 1 ファイルに限られる。

1. 数値は入力されたとおりに出る。
2. 否定句は削除も反転もされない。
3. 権限の記述は reader が判断できる形のまま残る。

- 権限は owner ではなく obligation で記述される。
- レビュー済みの結論だけを公開本文として扱う。

> 引用は連続する行を 1 段落に結合する。`>` は引用の印として解釈されるが、引用の中身は書き換えられない。

## コード表現はそのまま出る

Fenced code は中身を 1 文字も変えない。

```ts
const BLOCK_KINDS = ['heading', 'paragraph', 'list', 'code', 'blockquote', 'hr'] as const;
const isSameOrigin = (href: string, origin: string) => new URL(href, origin).origin === origin;
```

Inline code も同じで、`a < b && c > d` や `sum(n)` の演算子は HTML にも数式にも解釈されない。

## リンクの扱い

同じ origin へのリンクは [Decision 3](/portfolio) のように新しい tab を開かない。別 origin へのリンクは [W3C Internationalization](https://www.w3.org/International/) のように `target="_blank"` と `rel="noopener noreferrer"` を伴う。

## 未対応の構文は文字として残る

脚注は未対応である。`[^1]` という 4 文字と、その定義行 `[^1]: 定義` は、リンク化も削除もされない。

表も未対応である。

| 構文 | 判定 |
| --- | --- |
| 脚注 | 未対応 |
| 表 | 未対応 |

数式も未対応である。`$E = mc^2$` と `$$\sum_{i=1}^{n} i$$` はそのままの文字列として本文に残る。

取り消し線 `~~未確定~~`、task list `- [ ] 読書中`、定義リスト、4 段見出しも、同じ理由で文字として残る。

編集補助としての推敲は原稿側で行う。表示は検査ではなく定型チェックにすぎず、自動品質保証の証明にはならない。
