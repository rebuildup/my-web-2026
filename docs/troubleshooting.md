# Troubleshooting

> Recurring failures and how to diagnose them. Add to this document
> whenever a new failure mode is fixed.

## Install / bootstrap

### `pnpm install` warns `Ignored builds`

Expected at 0.1.0 for `esbuild`, `workerd`, and `@cloudflare/vite-plugin`.
Native binaries still resolve because they ship precompiled artefacts.
See `pnpm-workspace.yaml#onlyBuiltDependencies` for the allowlist.

### `pnpm install` errors `ERR_PNPM_IGNORED_BUILDS`

A new native-binary package was added without updating the allowlist.
Edit `pnpm-workspace.yaml#onlyBuiltDependencies` to include the
package, then re-run `pnpm install`.

### `pnpm install` cannot resolve `@tanstack/react-start-plugin-vite`

That package does not exist. The Vite plugin ships inside
`@tanstack/react-start`; import it from
`@tanstack/react-start/plugin/vite`.

### `panda codegen` fails with `value.match is not a function`

Breakpoints in `panda.config.ts` must be strings (`'640px'`), not
`{ value: '640px' }`. The runtime validator expects strings.

## Build / run

### `vite build` fails on a route under `src/routes/**`

The file must export `Route`. Move non-route work to the obligation that owns it (for example
`src/home/` for Home composition) or prefix the filename with `-`.

### `vite build` complains about `worker-configuration.d.ts`

Run `pnpm run cf-typegen` and commit the regenerated file.

### `wrangler deploy --dry-run` cannot find `@tanstack/react-start/server-entry`

The virtual module is generated by `@tanstack/react-start/plugin/vite`
during `vite build`. Run `pnpm run build` first, then retry.

### Hono path not intercepted

The path prefix is not in `EXTERNAL_BOUNDARY_PREFIXES` in
`src/server.ts`. Add the prefix and re-deploy.

## Type / lint

### `tsc --noEmit` complains about alias paths

`tsconfig.json#compilerOptions.paths` must mirror the Vite aliases
in `vite.config.ts#resolve.alias`.

### `tsc --noEmit` complains about `Env`

Run `pnpm run cf-typegen` so the bindings type is regenerated.

## Recovery

### Active ticket branch has no Draft PR

This is a delivery-surface bug. Open a Draft PR immediately with
the standard metadata. Do **not** continue implementation until
the PR exists.

### Release branch has merged content but no Draft release PR

This is also a delivery-surface bug. Open a Draft release PR
(`release-x-y-z -> main`) immediately. Do **not** continue
sprint work until the PR exists.

### Stack landing: middle of the stack shows merged but the

release trunk does not

The middle PR landed on an intermediate predecessor branch, not
on `release-x-y-z`. Reconcile by:

1. Rebase / merge the intermediate state onto `release-x-y-z`.
2. Re-validate the affected downstream branches at the new SHA.
3. Close the relevant Issues only after the landing is confirmed
   on `release-x-y-z`.
