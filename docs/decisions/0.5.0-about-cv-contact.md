This document is the canonical outcome of the Issue #79 obligation survey

implementation ticket (and any following ticket) can be drafted against
an explicit target, not against a re-litigated obligation.

## What we ship in 0.5.0

`/about` and `/contact` get **planned (0.5.0)** status. `/cv` gets
**deferred (0.6.0+)** — see "Why not /cv in 0.5.0" below.

### `/about` (single page, editorial coordinate system, story-first)

- one route under `src/routes/about.tsx`
- structure (per `docs/personal/domain.md` §12):
  - identity (`name`, current `handle`, current `role`)
  - interests (the throughlines that connect portfolio items)
  - experience (a **subset** of `/portfolio` items, narrative order, not the canonical list order — the list order is the loader's job)
  - current (today)
  - future (what is currently active vs parked)
- finds-me-elsewhere footer = a small inline list of external handles (X, GitHub, etc). Not a hub, not a `/links` route.
- no separate `/about/profile/*` or `/about/card/*` children

### `/contact` (single page, contact-policy authority)

- one route under `src/routes/contact.tsx`
- lists only channels that are currently active and whose purpose the
  page explicitly states (e.g. "採用お問い合わせ" or "技術的な議論").
  Channels that have not been re-verified at deploy time MUST NOT be
  listed — the page is fail-closed.
- no pricing / commission affordance on this surface. If a real
  commission flow exists in a future version, it gets its own route;
  it does not get bolted onto `/contact`.

## What we defer

### `/cv` → 0.6.0+

- Education / awards / career chronology is a **different** obligation
  from `/about`: `/about` is narrative-led, `/cv` is fact-led and
  machine-readable (often by recruiters' ATS or by LLM extraction).
- The data layer (canonical CV fact list with per-fact provenance and
  timestamps) does not exist yet on the 2026 side. The legacy `historyData`
  in `my-web-2025/about/data.ts` is not a contract and would have to be
  migrated through a real authority (`career-fact authority`), not
  hand-imported.
- The 0.5.0 release explicitly accepts "no `/cv` route" and does not
  stub one. The release notes MUST note this gap so a future hire
  reviewer does not conclude "missing".

### Commission / Pricing / Shop → uncommitted indefinitely

- Per ADR-0008: we do not pre-create obligations. Adding these requires
  an independent owner decision with a real downstream consumer (a real
  request flow, a real product offering). Until that lands, the
  capability rows stay `uncommitted` in `docs/domain/capabilities.md`.

## Why not bring back `/about/_AI` or `/links`

- `/about/_AI` was LLM-ingestion-oriented. Without a documented
  downstream consumer (an LLM-driven search engine that explicitly
  publishes its schema to which this profile would respond), the
  obligation is speculative. The operator's "don't bring back
  speculative surfaces" rule applies.
- `/about/links` was a linktree-style hub. The 2026 platform **owns**
  `/portfolio`; external handles that are not portfolio entries belong
  on `/about` as a footer list, not as a separate hub route.

## Why

The 0.5.0 priority is "短時間で採用担当者が人物像と実績を理解できる公開 surface". Today that priority is partially served by `/` + `/portfolio`. Adding `/about` and `/contact` closes the loop with `short path Home → identity → portfolio → evidence → contact`. `/cv` is the same obligation but a different contract (fact-led, machine-readable); deferring it does not regress the priority.

`/about` and `/contact` both pass the "no fabricated affordance" rule from `docs/personal/domain.md` §11: each only carries content for which the owner can stand behind the truth at deploy time.

## How to apply

- Future sprints that touch identity surfaces must read this decision
  before adding new routes. New routes that contradict the adopt /
  drop table above need a new decision doc.
- Adding `/links` or `/about/_AI` or `/about/card/real` again is a
  regression. If a future ticket wants them, it must first amend this
  decision document with a new obligation observation.
- `/cv` cannot be implemented as a "while we're at it" — its data layer
  (canonical CV fact list with provenance) is a separate obligation
  and needs its own issue cut against this decision.
