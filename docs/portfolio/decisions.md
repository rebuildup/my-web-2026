# Portfolio foundation — decisions log

This file records design decisions that the Issue text could not
fully capture, and the rationale behind them. Update this file
when a decision is reversed.

## Decision 1 — `facets` stays JSON-encoded TEXT, not a N:M table

**Status:** Accepted for the foundation (Issue #76).

**Context.** Issue #76 originally proposed a `project ⇄ facet` N:M
table. The implementation ships with `facets` as a JSON-encoded
TEXT column on `portfolio_project`.

**Why not N:M today.**

- The facet vocabulary is a closed enum today
  (`develop` | `video` | `design` | `other`) and small
  (≤ 4 values). A separate table adds JOIN overhead and an
  extra migration for no query-shape benefit at the current scale.
- `docs/domain/capabilities.md` treats `work-dev` /
  `work-video` / `work-design` as facet candidates, not as
  independent capabilities. Until that distinction becomes load-
  bearing, a JSON column is the simplest surface.
- The loader filters facets in-memory after a single SELECT
  because the page size is bounded (< 100 rows for the
  foundation). At that scale, a JSON-array scan is cheaper
  than maintaining a generated column or a N:M join.

**Promotion trigger.** Promote to N:M when ANY of:

1. The facet vocabulary exceeds ~16 distinct values (a JSON
   blob starts to dominate row size), OR
2. The facet set per row exceeds ~8 (rare in practice — most
   projects land on 1-3 facets), OR
3. A query needs to filter or aggregate rows BY facet from the
   opposite direction (e.g. "show me every row tagged `video`")
   without a full-table scan — at that point the in-memory
   filter on `listPortfolioProjects` is no longer acceptable.

When promoted, the N:M table becomes
`portfolio_project_facet (project_id, facet)` with a composite
PK and the JSON column is dropped. The loader contract does not
have to change — only the storage shape.

**Cross-references.**

- `src/portfolio/schema.ts` — documents the JSON encoding.
- `migrations/0007_portfolio.sql` — CHECK constraint enforces
  that each facet value is from the closed enum.
- `src/portfolio/load.ts` — the `intersectsAny` helper is the
  in-memory filter that N:M would replace at scale.

## Decision 2 — R2 media: metadata + nullable URL boundary, not a public route

**Status:** Accepted for the foundation (Issue #76). Public
delivery is deferred to Issue #77.

**Context.** Issue #76 originally framed "R2 公開 contract / media
配信" as a single deliverable. The implementation ships:

- `portfolio_media` table with full metadata
  (`r2_key`, `content_type`, `width`, `height`, `alt`, `caption`,
  `is_cover`, `display_order`).
- `composeMediaUrl(env, r2Key)` in `src/portfolio/media.ts`
  returning `null` while the public route is undecided.
- `R2_KEY_REGEX` validation that keeps accidental path traversal
  out of whatever URL builder we eventually ship.
- `PortfolioMedia.url: string | null` exposed to the UI, with
  the contract that `null` means "render a placeholder, do not
  crash".

**Why defer the public route.** Two competing designs need a
separate decision:

- **Signed URL per request.** Generated by the Worker, short
  TTL, fits the current egress model. Best for short-lived
  contexts (admin preview, signed-for-share).
- **Public R2 custom domain.** Long-lived cacheable URLs,
  served directly from R2 via Cloudflare's edge. Best for
  portfolio browsing where the same image is fetched many
  times.

The choice changes the cost model, the cache-control story,
and the security surface. Issue #76 should not lock it in.

**Ownership boundary.**

- Issue #76 (this foundation): the schema, the metadata
  contract, the R2 key validator, and the `null`-URL contract
  the UI must handle.
- Issue #77 (UI): the placeholder render, the actual public
  route choice, the Worker handler that signs / proxies, the
  R2 custom-domain wiring if we go that way.

**Cross-references.**

- `src/portfolio/media.ts` — composition entry point.
- `src/portfolio/schema.ts` — `PortfolioMedia.url: string | null`.
- `migrations/0007_portfolio.sql` — `portfolio_media` shape.

## Decision 3 — public visibility is the only contract this loader exposes

**Status:** Accepted (Issue #76 review feedback on PR #83).

**Context.** The original loader accepted an optional
`visibility` selector (`public | unlisted | draft`) and
returned `unlisted` rows on demand. That allowed a public
caller — anyone hitting the deployed server fn — to enumerate
or fetch rows the operator had marked unlisted.

**Why public-only here.**

- The TanStack Start server fns in `src/portfolio/public.ts`
  are unauthenticated by definition. Exposing a visibility
  selector to them is the same as exposing the unlisted
  catalogue to the open internet.
- The current loader's `isVisible` returned `true` for both
  `public` and `unlisted` rows; the SQL `IN`-clause then
  decided which rows to fetch. With selector removed, the
  SQL is hardcoded to `status='published' AND visibility='public'`
  and `isVisible` is reduced to defence-in-depth.

**Future admin / preview surface.** When one is needed, it
must be a separate entrypoint:

- A separate server fn module (e.g. `src/portfolio/admin.ts`)
  with its own validator (auth token / session / operator role).
- A separate loader impl (or an extended loader interface)
  that accepts the visibility selector internally — never
  reached from `src/portfolio/public.ts`.
- Unit-tested for the same boundary so the public surface
  cannot regress.

**Cross-references.**

- `src/portfolio/load.ts` — `isVisible` returns `true` only for
  `public + published`. SQL filter is hardcoded.
- `src/portfolio/public.ts` — the server-fn surface never accepts
  a `visibility` selector.
- `src/portfolio/load.test.ts` — `PUBLIC BOUNDARY` describe
  block covers draft / archived / unlisted / list containment.

## Decision 4 — cursor-based pagination with `id` as the final tiebreaker

**Status:** Accepted (Issue #76 → Issue #77 contract).

**Context.** Issue #77 requires cursor-based pagination for the
UI. The foundation loader needed a stable sort + opaque cursor
that survives concurrent row inserts without skip / duplicate.

**Sort key.** `pinned DESC, display_order ASC, updated_at DESC,
id ASC`. The first three cover operator intent; the fourth
(`id`) is the tiebreaker that prevents drift when two rows
share every other key. Without `id`, SQLite returns ties in
arbitrary order across pages and the caller can see the same
row twice (or miss one entirely) between consecutive requests.

**Cursor format.** Base64url-encoded JSON object with the four
sort-key fields of the last row in the previous page. Malformed
cursors are treated as "start from the first page" rather than
an error — the public surface prefers a fresh page to a 5xx
when a client ships a stale cursor.

**Tested invariant.**

- `cursor pagination: stable order with no skip / no duplicate`
- `cursor pagination: respects pinned-first ordering across pages`
- `cursor pagination: display_order ASC tiebreaker on updated_at`
- `cursor pagination: malformed cursor falls back to first page`

**Cross-references.**

- `src/portfolio/schema.ts` — `PortfolioCursor` + `encodeCursor` +
  `decodeCursor`.
- `src/portfolio/load.ts` — the SQL `WHERE` chain + `nextCursor`
  construction.
- `src/portfolio/load.test.ts` — `cursor pagination` describe
  block.

## Decision 5 — R2 media delivery: public R2 custom domain

**Status:** Accepted for the foundation (Issue #77). Implementation
follows once the operator configures the custom domain in the R2
bucket settings (not a code change — the Worker needs no route).

**Context.** #76 ships with `composeMediaUrl()` returning `null`.
Issue #77 picks the actual public delivery mechanism. Three
candidates were compared:

| axis | signed URL per request | Worker proxy | **R2 custom domain** |
| --- | --- | --- | --- |
| cacheability | low (TTL short) | low (per request) | **high (CDN + browser)** |
| complexity | medium (sign logic) | high (stream code) | **low (one DNS record)** |
| Worker request cost | **2× per image** (sign + fetch) | 1× per image | **0×** |
| security requirement | OK for both | OK for both | OK for public content |
| canonical URL stability | low (rotates) | medium (proxy URL) | **high (stable)** |
| OGP image use | needs stable URL | needs stable URL | **direct** |
| responsive / `srcset` | awkward (re-sign per src) | awkward | **natural** |

**Decision.** **R2 custom domain** for public portfolio media.
Portfolio images are public by design; there is no auth or private
context that justifies Worker-side signing or proxying. The R2
custom domain is configured at the bucket level and bypasses the
Worker entirely, so:

- Portfolio covers serve at e.g.
  `https://media.rebuildup.dev/portfolio/<slug>/cover.webp`.
- The Cloudflare edge caches the object; the browser caches per
  `Cache-Control`.
- Facebook / Twitter OGP crawlers fetch the URL directly without
  any Worker hop.
- `srcset` is a list of custom-domain URLs at different sizes.

**Why not Worker proxy.** A proxy is the right answer when the
content is private / per-user / needs server-side transformation.
For static public portfolio media it would just be a cost centre
with no upside.

**Why not signed URL.** Signed URLs rotate, so OGP crawlers (which
fetch once and cache) and `srcset` clients (which fetch the same
object at multiple sizes) would each have to re-sign. The signing
API also needs a Worker hop. That overhead is meaningful for
content that is identical for every visitor.

**Implementation.**

- `src/portfolio/media.ts` — `composeMediaUrl` returns the
  custom-domain URL when `env.MEDIA` is configured AND a
  `MEDIA_PUBLIC_BASE_URL` is available (read from `env`). When
  neither is set, it still returns `null` so the UI's
  placeholder branch is exercised.
- The custom domain itself is **not** a code change — it's an R2
  bucket setting in the Cloudflare dashboard. Until the operator
  wires it, every public URL is `null` and the UI renders the
  placeholder. The placeholder must be safe against null URLs and
  against missing R2 objects.

**Placeholder contract.** A `PortfolioMedia` row with `url === null`
or an `url` that fails to load must never crash the page. The UI
component renders a styled `media-empty` box (cover-sized frame
with a muted caption) and the loader still returns the row so
metadata (alt / caption / displayOrder) is reachable.

**Cross-references.**

- `src/portfolio/media.ts` — `composeMediaUrl` updated to compose
  the custom-domain URL when the env is configured.
- `src/portfolio/components/PortfolioMedia.tsx` — placeholder
  rendering branch.
- `migrations/0007_portfolio.sql` — `portfolio_media` shape
  unchanged.
