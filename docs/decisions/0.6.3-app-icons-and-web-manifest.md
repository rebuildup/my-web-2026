# Decision — 0.6.3 ファビコン / Apple Touch Icon / Web App Manifest

> Status: **Accepted**
> Issue: #504
> Target version: 0.6.3
> Grounded: 2026-10-18

Issue #504「favicon・Apple Touch Icon・manifestを整備」の実装判断を固定する。
既存ファビコン（Issue #285）は維持し、iOS ホーム画面アイコンと Web App Manifest を
**必要な範囲**で公開する。PWA のオフライン動作は宣言しない。

## 1. 何を公開するか / 何をしないか

| 公開するもの | 判断 |
| --- | --- |
| `rel="icon"` SVG（`/favicon.svg`） | Issue #285 の既存アセットをそのまま維持する |
| `rel="icon"` PNG 16 / 32 | SVG を読めない埋め込み・古い Safari のフォールバック |
| `rel="apple-touch-icon"` 120 / 152 / 167 / 180 | iOS がホーム画面で実際に求めるサイズ |
| `public/site.webmanifest`（`/site.webmanifest`） | name / short_name / lang / dir / id / start_url / scope / display / background_color / theme_color / icons のみ |
| manifest icons 192 / 512（`purpose: any`）+ 512（`purpose: maskable`） | Android / Chrome のランチャー向け |
| `theme-color` meta 2 本（light / dark） | サイトの 2 appearance（Issue #290）に合わせる |
| `_headers` の `/site.webmanifest` と `/icons/*` ルール | メディアタイプとキャッシュ方針の明示 |

| 公開しないもの | 理由 |
| --- | --- |
| service worker / オフラインキャッシュ | Issue #504 が明示的に禁止。プラットフォームにオフライン契約が無い |
| `apple-touch-startup-image` | 起動画面のアセットが存在しない。臆造しない |
| `share_target` / `shortcuts` / `display_override` / `categories` | 別 Issue の obligation 決定。gate で拒否する（§4） |
| `screenshots`（rich install UI 用） | 対応する device 実測が無く、条件を満たせない |
| 個人データ（氏名・連絡先・SNS handle） | manifest は公開済みサイト情報の写像に留める（§3） |
| 新しいブランド表現 | マークは既存 `public/favicon.svg` の円のみ（§2） |

## 2. マークの由来（推測の混入を止める）

`public/favicon.svg` の円（`#0000FF`）がマークの唯一の source of truth。
`scripts/generate-app-icons.mjs` がそこから PNG を生成し、**不透明キャンバスを敷くだけ**で
新しい形状・新しい色は作らない。

- 不透明キャンバスが必要な理由: iOS は alpha を持つ `apple-touch-icon` を**黒地に合成**する。
  生成スクリプトは `.flatten()` で alpha channel 自体を落とす（`hasAlpha === false`）。
- キャンバス色は `bg.canvas` の light step（`colors.neutral.0` = `#ffffff`）、マーク色は
  `public/favicon.svg` から parse する。gate は両方とも `src/editorial/tokens.ts` に実在することを要求する。
- `maskable` 用の円だけは 60% に縮尺する。Web App Manifest 側が定める safe zone は
  「中央 80% の円」であり、端まで 접した円は launcher のマスクで切れてしまうため。
  背景は full-bleed なので crop の縁は見えない。

## 3. 公開情報の authority

`docs/personal/knowledge-model.md` の「Visibility is independent from truth」/「Source authority is contextual」に従い、
manifest は**既存の公開 surface の写像**であり、独立した personal data を持たない。

- `name` / `short_name` = `my-web-2026`（`__root.tsx` の `<title>` と同一文字列。ここだけが唯一の source）。
- `lang: "ja"` = `<html lang="ja">` と一致。
- `start_url` / `scope` / `id` は origin  相対 path のみ。外部 origin を参照しない。
- 個人データ・連絡先・SNS handle は manifest に入れない。`/contact` が公開する内容は
  contact surface の authority（freshness gate）に属し、icon の義務ではない。

## 4. 監査対象（gate）

`scripts/check-app-icons.mjs`（`validate:fast` に組込み、`pnpm run check:app-icons`）が fail-closed で検査する:

1. `public/site.webmanifest` が parse でき、必須 member を持ち、**ticket が決定した member のみ**を持つ
2. `APP_ICON_LINKS` の全 `<link>` が実在ファイルへ解決し、`sizes` が実ピクセルと一致する
3. 全 PNG が alpha channel を持たず、中央ピクセル = マーク色 / 隅ピクセル = キャンバス色
4. `public/icons/` の全ファイルが head link か manifest から**ちょうど 1 回**参照される（orphan / 重複なし）
5. Issue #285 の SVG favicon と iOS の 4 サイズが宣言されたまま残っている
6. manifest の `theme_color` / `background_color` と `theme-color` meta 2 本の値が
   `src/editorial/tokens.ts` に実在する（設計システム外の色を持ち込めない）
7. `_headers` が manifest の `Content-Type` を固定し、`/icons/*` を revalidating に保つ
8. `src/**` に service worker 登録が無い（オフライン宣言の混入防止）

unit test（`scripts/check-app-icons.test.mjs`）は上記各項目の **mutation test** で、
gate が drift を検出できない場合（false green）を自ら検出する。

## 5. 検証の 3 層

| 層 | 対象 | 何が証明されるか |
| --- | --- | --- |
| static gate（Node） | head link / manifest / ファイル | 宣言された契約が整合していること |
| integration（workerd / `SELF.fetch`） | 実 SSR HTML | head merge が route 固有 `head()` を持つページでも icon family を残すこと |
| E2E（Chromium） | 実ブラウザ | 各 PNG が宣言サイズで decode され、manifest が JSON として fetch されること |

検証画面: `docs/verification/web/app-icons-preview.png`（local preview の実 Chromium による取得）。
秘密情報は含まれない（読み取るのは `document.head` と静的アセットのみ）。

## 6. 既知の制約 / 残リスク

- **`Content-Type` の production 実機確認**: `_headers` の `Content-Type: application/manifest+json` は
  local preview（`vite preview` が同ファイルを parse）で確認済み。Cloudflare Workers Static Assets 実機での
  応答ヘッダは production Smoke で確認する項目として残す。`.webmanifest` 拡張子自体も同値のマップを持つため、
  いずれの経路でも同じ型になる。
- **`purpose: "maskable"` の実 launcher 確認**: 60% 円 + full-bleed 背景は safe zone 仕様から導出した
   것이、Android 実機 / 実 launcher の見た目は未確認。視覚判断は owner の目を通す必要がある。
- **`display: "standalone"`**: manifest 仕様上 1 色しか指定できない `theme_color` のため、manifest 側は
  appearance 変化しない `brand.700`、head 側は light / dark の 2 本で表す。サイト側に offline が無い
  ことを利用者が誤解しないよう、PR / docs では offline 非宣言を明示する。
- **`share_target` 等を後々足す場合**: `ALLOWED_MANIFEST_MEMBERS` を拡張せずに追加すると gate が落ちる。
  これは意図的（member 追加 = obligation 決定）であり、Decision を先に書くこと。
