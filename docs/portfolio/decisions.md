# Portfolio foundation — decisions log

This file records design decisions that the Issue text could not
fully capture, and the rationale behind them. Update this file
when a decision is reversed.

## Decision 1 — `facets` stays JSON-encoded TEXT, not a N:M table

**Status:** Accepted for the foundation (Issue #76).

**Context.** Issue #76 originally proposed a `project ⇄ facet` N:M
table. The implementation ships with `facets` as a JSON-encoded
TEXT column on `portfolio_project`.

**Why not N:M today.**

- The facet vocabulary is a closed enum today
  (`develop` | `video` | `design` | `other`) and small
  (≤ 4 values). A separate table adds JOIN overhead and an
  extra migration for no query-shape benefit at the current scale.
- `docs/domain/capabilities.md` treats `work-dev` /
  `work-video` / `work-design` as facet candidates, not as
  independent capabilities. Until that distinction becomes load-
  bearing, a JSON column is the simplest surface.
- The loader filters facets in-memory after a single SELECT
  because the page size is bounded (< 100 rows for the
  foundation). At that scale, a JSON-array scan is cheaper
  than maintaining a generated column or a N:M join.

**Promotion trigger.** Promote to N:M when ANY of:

1. The facet vocabulary exceeds ~16 distinct values (a JSON
   blob starts to dominate row size), OR
2. The facet set per row exceeds ~8 (rare in practice — most
   projects land on 1-3 facets), OR
3. A query needs to filter or aggregate rows BY facet from the
   opposite direction (e.g. "show me every row tagged `video`")
   without a full-table scan — at that point the in-memory
   filter on `listPortfolioProjects` is no longer acceptable.

When promoted, the N:M table becomes
`portfolio_project_facet (project_id, facet)` with a composite
PK and the JSON column is dropped. The loader contract does not
have to change — only the storage shape.

**Cross-references.**

- `src/portfolio/schema.ts` — documents the JSON encoding.
- `migrations/0007_portfolio.sql` — CHECK constraint enforces
  that each facet value is from the closed enum.
- `src/portfolio/load.ts` — the `intersectsAny` helper is the
  in-memory filter that N:M would replace at scale.

## Decision 2 — R2 media: metadata + nullable URL boundary, not a public route

**Status:** Accepted for the foundation (Issue #76). Public
delivery is deferred to Issue #77.

**Context.** Issue #76 originally framed "R2 公開 contract / media
配信" as a single deliverable. The implementation ships:

- `portfolio_media` table with full metadata
  (`r2_key`, `content_type`, `width`, `height`, `alt`, `caption`,
  `is_cover`, `display_order`).
- `composeMediaUrl(env, r2Key)` in `src/portfolio/media.ts`
  returning `null` while the public route is undecided.
- `R2_KEY_REGEX` validation that keeps accidental path traversal
  out of whatever URL builder we eventually ship.
- `PortfolioMedia.url: string | null` exposed to the UI, with
  the contract that `null` means "render a placeholder, do not
  crash".

**Why defer the public route.** Two competing designs need a
separate decision:

- **Signed URL per request.** Generated by the Worker, short
  TTL, fits the current egress model. Best for short-lived
  contexts (admin preview, signed-for-share).
- **Public R2 custom domain.** Long-lived cacheable URLs,
  served directly from R2 via Cloudflare's edge. Best for
  portfolio browsing where the same image is fetched many
  times.

The choice changes the cost model, the cache-control story,
and the security surface. Issue #76 should not lock it in.

**Ownership boundary.**

- Issue #76 (this foundation): the schema, the metadata
  contract, the R2 key validator, and the `null`-URL contract
  the UI must handle.
- Issue #77 (UI): the placeholder render, the actual public
  route choice, the Worker handler that signs / proxies, the
  R2 custom-domain wiring if we go that way.

**Cross-references.**

- `src/portfolio/media.ts` — composition entry point.
- `src/portfolio/schema.ts` — `PortfolioMedia.url: string | null`.
- `migrations/0007_portfolio.sql` — `portfolio_media` shape.

## Decision 3 — public visibility is the only contract this loader exposes

**Status:** Accepted (Issue #76 review feedback on PR #83).

**Context.** The original loader accepted an optional
`visibility` selector (`public | unlisted | draft`) and
returned `unlisted` rows on demand. That allowed a public
caller — anyone hitting the deployed server fn — to enumerate
or fetch rows the operator had marked unlisted.

**Why public-only here.**

- The TanStack Start server fns in `src/portfolio/public.ts`
  are unauthenticated by definition. Exposing a visibility
  selector to them is the same as exposing the unlisted
  catalogue to the open internet.
- The current loader's `isVisible` returned `true` for both
  `public` and `unlisted` rows; the SQL `IN`-clause then
  decided which rows to fetch. With selector removed, the
  SQL is hardcoded to `status='published' AND visibility='public'`
  and `isVisible` is reduced to defence-in-depth.

**Future admin / preview surface.** When one is needed, it
must be a separate entrypoint:

- A separate server fn module (e.g. `src/portfolio/admin.ts`)
  with its own validator (auth token / session / operator role).
- A separate loader impl (or an extended loader interface)
  that accepts the visibility selector internally — never
  reached from `src/portfolio/public.ts`.
- Unit-tested for the same boundary so the public surface
  cannot regress.

**Cross-references.**

- `src/portfolio/load.ts` — `isVisible` returns `true` only for
  `public + published`. SQL filter is hardcoded.
- `src/portfolio/public.ts` — the server-fn surface never accepts
  a `visibility` selector.
- `src/portfolio/load.test.ts` — `PUBLIC BOUNDARY` describe
  block covers draft / archived / unlisted / list containment.

## Decision 4 — cursor-based pagination with `id` as the final tiebreaker

**Status:** Accepted (Issue #76 → Issue #77 contract).

**Context.** Issue #77 requires cursor-based pagination for the
UI. The foundation loader needed a stable sort + opaque cursor
that survives concurrent row inserts without skip / duplicate.

**Sort key.** `pinned DESC, display_order ASC, updated_at DESC,
id ASC`. The first three cover operator intent; the fourth
(`id`) is the tiebreaker that prevents drift when two rows
share every other key. Without `id`, SQLite returns ties in
arbitrary order across pages and the caller can see the same
row twice (or miss one entirely) between consecutive requests.

**Cursor format.** Base64url-encoded JSON object with the four
sort-key fields of the last row in the previous page. Malformed
cursors are treated as "start from the first page" rather than
an error — the public surface prefers a fresh page to a 5xx
when a client ships a stale cursor.

**Tested invariant.**

- `cursor pagination: stable order with no skip / no duplicate`
- `cursor pagination: respects pinned-first ordering across pages`
- `cursor pagination: display_order ASC tiebreaker on updated_at`
- `cursor pagination: malformed cursor falls back to first page`

**Cross-references.**

- `src/portfolio/schema.ts` — `PortfolioCursor` + `encodeCursor` +
  `decodeCursor`.
- `src/portfolio/load.ts` — the SQL `WHERE` chain + `nextCursor`
  construction.
- `src/portfolio/load.test.ts` — `cursor pagination` describe
  block.

## Decision 5 — R2 media delivery: public R2 custom domain

**Status:** Accepted for the foundation (Issue #77). Configuration
follows once the operator attaches the `media.rebuildup.dev`
custom domain at the R2 bucket level (not a code change — the
Worker needs no route). The `MEDIA_PUBLIC_BASE_URL` value is
pinned in `wrangler.production.jsonc#vars` so the Worker
production deployment sees the canonical base URL without
operator runtime action.

**Context.** #76 ships with `composeMediaUrl()` returning `null`.
Issue #77 picks the actual public delivery mechanism. Three
candidates were compared:

| axis | signed URL per request | Worker proxy | **R2 custom domain** |
| --- | --- | --- | --- |
| cacheability | low (TTL short) | low (per request) | **high (CDN + browser)** |
| complexity | medium (sign logic) | high (stream code) | **low (one DNS record)** |
| Worker request cost | **2× per image** (sign + fetch) | 1× per image | **0×** |
| security requirement | OK for both | OK for both | OK for public content |
| canonical URL stability | low (rotates) | medium (proxy URL) | **high (stable)** |
| OGP image use | needs stable URL | needs stable URL | **direct** |
| responsive / `srcset` | awkward (re-sign per src) | awkward | **natural** |

**Decision.** **R2 custom domain** for public portfolio media.
Portfolio images are public by design; there is no auth or private
context that justifies Worker-side signing or proxying. The R2
custom domain is configured at the bucket level and bypasses the
Worker entirely, so:

- Portfolio covers serve at e.g.
  `https://media.rebuildup.dev/portfolio/<slug>/cover.webp`.
- The Cloudflare edge caches the object; the browser caches per
  `Cache-Control`.
- Facebook / Twitter OGP crawlers fetch the URL directly without
  any Worker hop.
- `srcset` is a list of custom-domain URLs at different sizes.

**Why not Worker proxy.** A proxy is the right answer when the
content is private / per-user / needs server-side transformation.
For static public portfolio media it would just be a cost centre
with no upside.

**Why not signed URL.** Signed URLs rotate, so OGP crawlers (which
fetch once and cache) and `srcset` clients (which fetch the same
object at multiple sizes) would each have to re-sign. The signing
API also needs a Worker hop. That overhead is meaningful for
content that is identical for every visitor.

**Implementation.**

- `wrangler.production.jsonc#vars` — `MEDIA_PUBLIC_BASE_URL:
  "https://media.rebuildup.dev"`. Non-secret config is committed
  to the repo so the operator does not need to set anything via
  the dashboard on every deploy. Production dry-run must include
  this entry.
- `wrangler.jsonc` (local) — intentionally **omits**
  `MEDIA_PUBLIC_BASE_URL`. Local dev sees every URL as `null` and
  exercises the placeholder branch by default; the variable can
  be set explicitly when the operator wants to test the
  custom-domain path locally.
- `src/portfolio/media.ts` — `composeMediaUrl` returns the
  custom-domain URL when `env.MEDIA` is configured AND a
  `MEDIA_PUBLIC_BASE_URL` is available (read from `env`). When
  neither is set, it still returns `null` so the UI's
  placeholder branch is exercised.
- The custom domain itself is **not** a code change — it's an R2
  bucket setting in the Cloudflare dashboard. Until the operator
  wires it at the bucket level, every public URL is `null` even
  though the Worker sees the base URL. The placeholder must be
  safe against null URLs and against missing R2 objects.

**Release prerequisite — durable state.**

The bucket-level attachment (R2 bucket `my-web-2026` ↔ custom
domain `media.rebuildup.dev`) is the only piece of Decision 5
that cannot be expressed as code. It lives in the Cloudflare
account's R2 settings, not in this repository. The release gate
that ships 0.5.0 must verify the attachment is live
(read-back: `wrangler r2 bucket domain list` or dashboard) before
the production dry-run can prove a single image actually serves.
The local dev path remains null, by design.

**Placeholder contract.** A `PortfolioMedia` row with `url === null`
or an `url` that fails to load must never crash the page. The UI
component renders a styled `media-empty` box (cover-sized frame
with a muted caption) and the loader still returns the row so
metadata (alt / caption / displayOrder) is reachable.

**Cross-references.**

- `src/portfolio/media.ts` — `composeMediaUrl` updated to compose
  the custom-domain URL when the env is configured.
- `src/portfolio/components/PortfolioMedia.tsx` — placeholder
  rendering branch.
- `migrations/0007_portfolio.sql` — `portfolio_media` shape
  unchanged.

**Amendment (Issue #459) — a custom domain serves every key.**

Decision 5 fixes *how* a published image is delivered, not *which
images may be*. Once the custom domain is attached (a Cloudflare
account setting; this repository cannot confirm the production
attachment), any key that exists in the bucket is readable by anyone
who can guess it, so `composeMediaUrl` now consults the R2 visibility
boundary (`src/cloudflare/media-visibility.ts`) and returns `null` for
any key outside a declared public namespace. The decision itself is
unchanged — public delivery via a custom domain is still the right
mechanism for published portfolio media — but the namespace contract,
the code paths it is enforced on, and the bucket-level obligation that
follows from it are now written down in
[`docs/security/r2-media-visibility.md`](../security/r2-media-visibility.md).

## Decision 6 — untrusted article bodies: one href oracle, one visible refusal

**Status:** Accepted (Issue #451).

**Context.** Article bodies are editor-controlled and, for the
Notion-sourced material, third-party-controlled. The Markdown lexer
already refused raw HTML by not parsing it, and already stripped
non-`http(s)` link targets — but it did so silently, rewriting a
refused href to `#`. A silently rewritten link is indistinguishable
from a broken one: the author sees a dead anchor, a reviewer sees
nothing, and the only trace of an attack attempt is gone.

**Decision.**

- `classifyHref` (`src/portfolio/markdown.lexer.ts`) is the **single
  href oracle**. `safeHref` / `isExternalHref` are compatibility
  wrappers over it, so no caller can hold a second opinion about what
  is safe.
- Scheme policy: `http:` / `https:` / root-relative / fragment.
  Control-character and character-reference obfuscation are resolved
  before the check, and protocol-relative hrefs are resolved and
  treated as external rather than passed through as internal paths.
- A refused href renders as an **inert, visible marker**
  (`portfolio-md-link-blocked`, with `data-blocked-reason` and
  `data-blocked-href`), never as an anchor. The reasons are an
  enumerated set (`empty`, `control-character`,
  `scheme-not-allowed`, `encoded-scheme`, `unparsable`) so the visible
  error names the actual cause.
- Notion-derived HTML has exactly one entry point,
  `sanitizeNotionHtml` (`src/portfolio/markdown.notion.ts`): element
  and attribute allow lists, active subtrees dropped, URL attributes
  delegated to `classifyHref`, refusals returned rather than
  discarded, no exceptions on malformed input.

**Why not a sanitiser library.**

A dependency that parses HTML would bring its own parser, its own
allow-list, and its own CVE surface into a Worker bundle, to convert
a shape we do not ingest yet. A ~300-line adapter in the obligation
that owns the renderer is auditable in review, bounded by design
(depth + output ceilings), and refuses to throw. Revisit when an
ingest path actually needs HTML, and prefer promoting one library
over maintaining a second home-grown parser.

**Why not delete the payload instead of escaping it.**

Escaping keeps the refusal reviewable: the screenshot and the served
page show the exact payload that was neutralised. Silent deletion
would also pass "nothing executes" while destroying the evidence.

**Cross-references.**

- `src/portfolio/markdown.lexer.ts` — the oracle.
- `src/portfolio/markdown.notion.ts` — the HTML adapter.
- `test/fixtures/markdown-xss-fixtures.ts` — the shared corpus.
- `docs/security.md` §"Markdown / Notion-derived HTML input boundary".
## Decision 7 — unsupported Markdown degrades to literal text, and locale stays opt-in

**Status:** Accepted (Issue #435). No behaviour change ships with this
Decision — it records the contract the safety suite pins.

**Context.** Issue #77 shipped the minimal Markdown renderer with an
explicit list of omissions (tables, images, footnotes, math, …). Two
questions were left unanswered, and both are answerable from the
repository rather than from preference:

1. What does an operator SEE when a published body contains one of
   those unsupported constructs?
2. Who owns the line between "the renderer changed my text" and "the
   renderer did not"?

A writing-assistance tool such as [yomiyasu](https://github.com/nanaism/yomiyasu)
was referenced in the Issue. It edits prose; it is not a quality gate,
and adopting it must not turn a text-editing aid into a claim of
automated quality assurance. Python is not added as a required
runtime.

**Decision.**

- **Unsupported syntax degrades to literal text, with two recorded
  exceptions.** Footnote markers, pipe tables, `$…$` / `$$…$$`,
  `~~…~~`, heading levels past `###`, definition lists, setext
  headings and reference links are NOT dropped and NOT silently
  transformed: they stay in the rendered paragraph as the characters
  the operator typed. Silent deletion would change the meaning of an
  article without evidence; literal text is visible, reviewable and
  reversible.
- **The two exceptions are shape changes, never meaning or safety
  changes.** `![alt](url)` splits into the character `!` plus the
  SUPPORTED `[alt](url)` link syntax, so it renders as `!` followed by
  an anchor — `![](url)` renders `!` plus a nameless anchor. No `<img>`
  is created and the URL still goes through the link policy. External
  targets get `rel="noopener noreferrer"`; a dangerous scheme does not
  become an anchor at all — it renders the visible, inert blocked
  marker from Decision 6 (`data-blocked-reason` / `data-blocked-href`).
  Likewise a line-initial `- [ ] task` consumes the
  supported `- ` list marker and renders `<ul><li>[ ] task</li></ul>`;
  only the inline code-span form stays literal. Meaning survives in
  all three cases, but the SHAPE does not, and an operator has to be
  told that rather than discovering it in production. All three
  behaviours are pinned by `src/portfolio/markdown.safety.test.tsx` and
  stated per-construct in `docs/portfolio/markdown-format.md` § 3.
- **Safety, typography and text quality are three separate claims.**
  The renderer owns the first two and can be tested for them. It owns
  neither the third nor publication: `src/portfolio/load.ts` decides
  what is public (Decision 3), and a reviewer decides whether a claim
  was verified. A renderer test can prove "the renderer did not alter
  the words"; it can never prove "the words were correct".
- **Locale is opt-in at the consuming surface, never inferred.** The
  renderer takes `source` and `siteOrigin`, and nothing else. It emits
  no `lang` / `dir`, performs no smart quotes, ellipsis folding, dash
  substitution or CJK line-break rule, and switches no font by locale.
  A future feature that genuinely needs locale (Japanese kinsoku, for
  example) must be opted into explicitly by the surface that needs it
  and must arrive under its own ticket — never as a global default.

**Known limitation recorded, not fixed.** Intraword `_` becomes
emphasis (CommonMark would not), so a bare `MAX_RETRY_COUNT` renders
as `MAXRETRYCOUNT`; authors are told to write identifiers in a code
span, which is byte-exact. It is pinned by a test so a future fix is a
deliberate, visible change, and it changes how already-published
bodies read, which is an owner decision rather than a test-suite
decision. (The former "stripped-scheme link keeps `target=_blank`"
limitation was removed by Decision 6 / Issue #451: a refused href is no
longer rendered as an anchor with `href="#"`, so there is no dead
anchor left to inherit the target.)

**Cross-references.**

- `docs/portfolio/markdown-format.md` — the full contract, the
  unsupported-syntax matrix and the reproduction commands.
- `src/portfolio/fixtures/markdown/` — the two fixtures the suite,
  the Storybook stories and the report generator all read.
- `src/portfolio/markdown.safety.test.tsx` — the fixture-level suite.
- `scripts/markdown-format-report.mjs` — the verification report whose
  screenshot the Issue asks for.
