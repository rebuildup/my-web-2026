# i18n と URL identity

> Status: **Canonical text policy**
> Visibility: public (MIT)
> Audience: contributor, agent, future-self
> Decision record: [`../adr/ADR-0017-unicode-normalization-and-url-slug-separation.md`](../adr/ADR-0017-unicode-normalization-and-url-slug-separation.md)
> Evidence: [`../verification/i18n/unicode-slug-validation.md`](../verification/i18n/unicode-slug-validation.md)
> Enforced by: `pnpm run i18n:policy:check` (part of `validate:fast`)

## 1. 結論

このプラットフォームのテキストは **2 つの別の identity** であり、別の契約で扱う。

| | 表示本文 (display text) | URL slug |
| --- | --- | --- |
| 誰が読むか | 人間 | 機械（path segment） |
| 所有者 | `src/i18n/` が**規則**を所有。各 surface が**値**を所有 | 各 obligation が**grammar**を所有。`src/i18n/` が適用規則を所有 |
| 正規化 | しない（保持）。比較用の NFC fold のみ | しない。導出もしない |
| 非 ASCII | そのまま表示 | **拒否**（`non-ascii`） |
| 変更の承認 | 編集者 | 編集者（URL は公開後に変えられない） |

## 2. 表示本文の契約

- 記述された byte 列を保持する。D1 → row → model → DOM のどこかで再構成しない。
- 正規化するのは**比較**のときだけ（`foldForComparison` = NFC）。比較キーは storage / URL / DOM に出さない。
- 互換正規化（NFKC / NFKD）は**報告だけ**して適用しない。`describeUnicode().compatibilityFoldChanges` が何を壊すかを示す。
- `assertDisplayTextPreserved(original, current, field)` は**変換のある seam** 用の `===` 検査。
  変換前の raw 値と変換後の値を比べる 것이用法であり、**同じ式を 2 回渡しても無効**（恒真で絶対に落ちない）。
  現在の row → model マッピングは identity（代入であって計算ではない）なのでこの検査は使っておらず、
  「row → model が byte-exact」は `src/portfolio/schema.test.ts` が直接固定している。

### NFC と NFD は同じ単語

`café`（U+00E9 の 1 code point）と `café`（`e` + U+0301 の 2 code point）は同じ単語の 2 表記。
表示は著作者の綴り、比較は NFC の一致、URL にはどちらも出さない。
この 3 つを混ぜないことが衝突しない理由である。

## 3. slug の契約

- **導出しない**。`title` から `slug` を計算する処理を持たない。
- 既存の owner grammar が唯一の受理基準:
  - emoji: `^[a-z][a-z0-9_]*$`、1..16 文字（`src/reactions/slug-regex.ts` が所有）
  - portfolio: `^[a-z0-9][a-z0-9-]{0,127}$`、1..128 文字（`src/portfolio/schema.ts` が所有）
- 拒否理由（`classifySlugCandidate`）:

  | reason | 意味 |
  | --- | --- |
  | `not-a-string` | 型が違う |
  | `empty` | 公開するものが無い |
  | `non-ascii` | **ポリシー拒否**。transliterate / fold / mark 除去は行わない |
  | `too-long` | owner の上限超過 |
  | `grammar-mismatch` | ASCII だがこの owner の grammar に合わない |

- `non-ascii` は長さ・pattern より**先**に判定する。理由が「pattern の偶然」ではなく「ポリシー」であることが区別できること。

### 3.1 まだ分類していない URL 空間（`/tools/$slug`）

`/tools/<slug>` も公開 URL 空間だが、**このポリシーの分類を通っていない**。loader が
`params.slug.toLowerCase()`（Issue #183 の display-case 許容）で lookup key を作っており、
`classifySlugCandidate` を呼ばないため `/tools/MultiSlicer` と `/tools/multislicer` は
同一の公開 identity に解決する。grammar 自体は
`src/tools/manifest.schema.json` が所有する ASCII 限定表現なので、現時点で非 ASCII が
この path に入ることはない。決していないのは case folding の許容だけである
（`classifySlugCandidate` を通す＝許容を廃止する / 恒久的な例外として明記する、
のどちらかを owner が選ぶ）。

**`pnpm run i18n:policy:check` はこれを検査しない**。URL parameter の case folding に対応する
rule が無いためであり、この gap は
[ADR-0017 §6.4](../adr/ADR-0017-unicode-normalization-and-url-slug-separation.md) に
記録されている。gate が green でも「すべての slug 空間が分類済み」とは言えない。

## 4. なぜ拒否するのか（衝突の測定）

一般的な slugify（NFKD + 結合記号除去）を採用した場合:

| 入力 | naive slug | 起きること |
| --- | --- | --- |
| `5 µm tolerance` / `5 μm tolerance` | 両方 `/5-m-tolerance` | 別の 2 文字が 1 つの URL を共有する |
| `ＭＵＬＴＩ slicer` / `Multi slicer` | 両方 `/multi-slicer` | 全角表記が ASCII プロジェクトの URL を乗っ取る |
| `N ≠ 3 (非対応)` | `/n-3` | 否定が消える（`≠` は mark 除去で `=` になる） |
| `① 優先` | `/1` | 数値が変わる |
| `Ⅳ 期` | `/iv` | 数値が変わる |

URL は公開後に取り消せない。拒否なら URL 空間は単射のまま、保てば衝突は恒久化する。

## 5. 文章品質とタイポグラフィは別

Issue #433 はこの 2 つを明確に分離する。

| | 文章品質 (copy quality) | タイポグラフィ (typography) |
| --- | --- | --- |
| 対象 | 言葉の選択、否定、数値、単位、主張 | 字体・字間・行間・折り返し |
| 誰の仕事 | 編集者（owner） | CSS / font stack |
| このプラットフォームの姿勢 | **評価も修正もしない**。校正ツールは補助であり、自動品質保証の証明ではない | `src/editorial/` が visual language を所有。webfont は declaration のみで、font stack は製品と同じものを宣言する |
| 互換正規化との関係 | `① → 1` / `µ → μ` / `≠ → =` は**意味**を変えるため不可 | `㎡ → m2` は意味を保った**見た目**の変換だが、同じ手順で意味変更も起きるため採用しない |

校正ライブラリ（例: yomiyasu）を採用する場合も、それは**編集補助**であり、本ポリシーや自動品質保証の代替にはならない。Python をこのプラットフォームの実行必須ランタイムにしない。

## 6. locale は必要な功能で opt-in

- `Intl` 系は **locale を明示した呼び出しだけ**が許可される（`new Intl.NumberFormat('en-US')`）。
- locale なしの `toLocaleString()` / `new Intl.NumberFormat()` は訪問者環境に依存し、同じレコードが訪問者ごとに違う値になるため禁止。
- `scripts/check-i18n-policy.mjs` の `explicit-locale` / `intl-without-locale` が機械的に強制する。
- `<html lang="ja">` はサイト全体の宣言であり、この opt-in ルールとは別物（renderer / assistive technology 向けの宣言）。
- 訪問者 locale を尊重する表示を今後足す場合は、fallback と SSR/hydration の一致を先に定義すること。

## 7. 検証方法

```bash
pnpm run i18n:policy:check          # 判断表 17 行 + 出荷済みソースの policy 検査
pnpm exec vitest run src/i18n/      # policy の契約テスト
pnpm run capture:i18n-verification  # 検証画面の再生成
```

判断表（`src/i18n/fixtures.ts`）は test・gate・capture の 3 者が共有する。どれか 1 つが古いまま残らないこと。

## 8. このポリシーが**しない**こと

- 本文の校正・言い換え・要約。
- 訪問者 locale への追随。
- slug の自動生成、transliteration、mark 除去、cut & retry。
- `/tools/<slug>` の case folding（`/tools/MultiSlicer` と `/tools/multislicer` は同一 identity）。
  現状の許容は Issue #183 の既存挙動であり、§3.1 のとおり未決。
- `<非ASCII>` の portfolio URL が 404 になるべきかという route 契約の決定（別 ticket）。
