## 1. 画像配信停止の原因と復旧

### 原因（実測）

公開 README の `/profile` SVG は GitHub camo 経由で配信される。
camo は origin fetch にタイムアウトを持ち、v0.14.0 の `/profile` は
**request 時に GitHub API を複数呼ぶ**構造（stats / topLangs / streak /
avatar、microCache コールド時）で **6.5–9 秒** を要していた。

実測（デプロイ前）:

```text
GET /api/v1/github-profile/profile?theme=dark  → 200, 6.5–9.2s（3連続）
camo …/profile?theme=dark                     → HTTP 504（camo が origin を断念）
camo …/showcase.webp                          → 200（13.2s だが完走）
```

→ camo 504 により GitHub 上でプロフィール画像が壊れて表示されていた。
「停止」ではなく「遅延起因の camo タイムアウト」が正体。

### 復旧（v0.15.0 の構造変更そのものが修正）

ADR-0027 のスナップショット駆動へ移行し、request 時の上流呼出を全廃。
D1 読みのみになった結果:

```text
GET /vitals          → 200, 0.43s
GET /top-languages   → 200, 0.48s
GET /profile         → 200, 1.37s（旧 6.5–9s → 約 1/6）
GET /identity        → 200, 0.53s
GET /stack           → 200, 1.61s
GET /activity-map    → 200, 0.78s
camo /profile?theme=dark → 200, 0.83s（旧 504 から復旧）
```
