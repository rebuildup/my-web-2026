# ADR-0027: プロフィール配信面のデータ源単位分割と GitHub 統計範囲拡張

- Status: Accepted (2026-11-26)
- Supersedes: visual doc §21/§22 の「単一 `/profile` SVG を最終構成
  とする」配信単位の決定。§22 のグリッド・階層・構図契約は継続有効。
- Issue: my-web-2026#1235, #1240, #1241, #1242 + 本 ADR 起票 Issue
- 正本: `docs/visual/github-profile-readme.md` §23

## 1. 背景

v0.14.0 で `/github-profile/profile` 単一 SVG に Identity・
Activity・Stack を統合した（#1235 round 2）。視覚統合は達成された
が、ユーザーレビューで 2 つの構造的問題が指摘された。

1. **配信単位**: データ依存も更新周期も異なる要素（presence の
   15 分鮮度、GitHub snapshot、静的スタック資産）を 1 レスポンス
   に束ねると、鮮度・キャッシュ・障害分離の設計余地がない。
   画像リクエストを起点とした同期実行構造からの脱却が要求された。
2. **集計範囲**: GitHub 統計が個人所有リポジトリ中心で、
   Organization・参加プロジェクト・外部コントリビュート先の
   活動を網羅していない。「all-time」表記と実取得期間の不整合、
   旧/現行 Rank 算出の差異も未検証。

## 2. 決定

### 2.1 配信面はデータ源単位に分割する

Identity / Presence / Vitals / Activity / Top Languages / Stack を
更新周期・データ依存・キャッシュ境界に適した単位で分割する。
視覚的統一（グリッド・階層・構図・プレートとしての面）は維持し、
分割は配信と鮮度の設計であって構図の再設計ではない。

- パイプライン分離: **非同期同期 → 永続スナップショット（D1）→
  画像生成 → 配信**。画像リクエストが上流 API 呼び出しを誘発
  しない。
- 既存基盤優先: D1 ingest（`/api/v1/activity/github`）、
  `sync-github-activity.mjs`、Infisical、Cache API。
  新規課金インフラ・従量課金の導入なし。
- 各単位が独立に: 鮮度管理・Last Known Good・障害分離・
  重複同期防止・キャッシュ無効化・失敗時 honest 表示を持つ。
- `microCache` の TTL 不整合（コメント 5 秒 vs 実装 500 秒）を
  修正する。
- `/profile` は公開 README 切替まで互換維持（同一モデルの
  合成ラッパ）。分割前後でサイズ・応答時間・上流呼出数・
  キャッシュヒット・障害時表示を計測比較する。

### 2.2 GitHub 統計の集計範囲を実態へ拡張する

- 対象監査: `stats.ts` / `top-languages.ts` /
  `calculateRank.ts` / `streak-fetcher.ts` /
  `sync-github-activity.mjs` と関連 API・データ契約。
- Organization・参加プロジェクト・外部コントリビュート先を
  GitHub API の発見・検索経路で動的に列挙（org 名固定なし）。
  ページネーション・重複排除・権限差・レート制限・増分同期を
  設計する。
- 指標分離: 所有 repo 言語構成 / 参加 repo 言語構成 / 本人の
  コード変更量 / 本人の活動数。Stars 等は所有と参加を区別。
- 公開境界維持: 非公開 repo・Organization 識別情報は既存の
  anonId/HMAC・fail-closed 契約を継続。
- Rank: 旧方式と現行方式を同一入力で比較し、集計範囲拡張の差分を
  検証。恣意的な引き上げではなく実態に合った集計を成立させる。
- 「all-time」表記と実取得期間の不整合を是正。

### 2.3 継続する視覚改善

モチーフアイコン・数値/ラベルのグルーピング・余白・構造化を
#1240 系として継続。全面再設計は行わない。

## 3. 結果

- 配信面・鮮度・障害分離がデータ源ごとに独立し、片方の stale が
  他方を止めない（ADR-0026 §2.1 の精神を全 surface へ拡張）。
- 統計が「個人所有 repo の内訳」ではなく「本人の公開活動の
  実態」を反映し、指標の意味が名前と一致する。
- 単一 SVG の視覚的成果（構図・グリッド・階層）は資産として
  継承し、実装単位だけが変わる。
